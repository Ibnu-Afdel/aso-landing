## Requirements

- [uv](https://docs.astral.sh/uv/), for Python dependencies and running commands.
- Python 3.12 or newer.
- Node 22 or newer, for the Vite dev server and the frontend build.

## Create a project

```bash
uvx aso new myapp
```

This creates `myapp/`, installs the Python dependencies with `uv sync`, installs the npm
packages, generates an application key, and runs the first migration (the `users`,
`sessions`, `password_reset_tokens`, and `failed_jobs` tables). You get a working app before
you've written a line of code.

## Run it

```bash
cd myapp
uv run aso dev
```

`aso dev` starts the Python server, the Vite dev server, and the typed-routes watcher
together, and prints where to look:

```
  App   http://127.0.0.1:8000  <- open
  Vite  http://localhost:5173  (hot reload)
```

Open the app URL, not the Vite URL — Vite only serves assets; the app itself is the Python
server. If port 8000 is taken, `aso dev` picks the next free one.

<Callout type="tip">
Commands in these docs are written as `aso ...`. Inside a project, run them as
`uv run aso ...`, or activate the virtual environment once with `source .venv/bin/activate`.
</Callout>

## Project structure

```
myapp/
├── app/
│   ├── http/
│   │   ├── controllers/     # one class per resource, e.g. post_controller.py
│   │   └── requests/        # FormRequest validation classes
│   ├── models/               # Model subclasses, e.g. post.py -> Post
│   └── policies/             # authorization, e.g. post_policy.py
├── bootstrap/app.py          # create_app(): builds the FastAPI app
├── config/                   # app, auth, database, mail, session, ... (.py)
├── database/
│   ├── migrations/           # Alembic revision files
│   └── factories/            # test data factories
├── resources/
│   ├── js/
│   │   ├── app.tsx           # createInertiaApp
│   │   ├── pages/            # one .tsx per Inertia page, e.g. posts/index.tsx
│   │   └── routes/ actions/  # generated by `aso routes:generate`
│   └── views/app.html        # the Inertia root template
├── routes/
│   ├── web.py                # session + CSRF + Inertia routes
│   └── api.py                 # stateless JSON routes, /api prefix
├── tests/
│   ├── feature/
│   └── architecture/
├── AGENTS.md                 # rules for AI coding agents
└── .env
```

## The `.env` file

Configuration lives in `.env`, read through `config/*.py`. A new app defaults to SQLite
(`DB_DATABASE=database/database.sqlite`), the `sync` queue driver, and `log` mail (every
outgoing email is written to `storage/logs/`, so nothing leaves your machine while you build).
Switch to Postgres, Redis, or SMTP by changing `.env` — the code in your app doesn't change.

## Check your setup

```bash
aso doctor
```

`doctor` checks your Python version, the `.env` file, the database connection, pending
migrations, the frontend build, and that every `inertia("some/page")` call has a matching
page component. A healthy app prints:

```
Everything looks healthy!
```

## For AI coding agents

Every app ships with an `AGENTS.md`: generator commands to prefer, the architecture rules
(`A1`–`A13`) your test suite enforces, and the project's naming conventions. Point your coding
agent at it before it touches the codebase — the architecture tests will catch violations
either way, but the file saves a round trip.
