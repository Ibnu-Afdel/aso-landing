Every Aso app ships `tests/architecture/test_architecture.py`, which runs a set of AST-based
checks over your own code — not a linter you configure, a test that fails the suite the same
way any other assertion would:

<CodeFile name="tests/architecture/test_architecture.py">
```python
from aso.testing.arch import arch_preset

def test_aso_preset() -> None:
    arch_preset("aso").check()
```
</CodeFile>

These rules exist because the framework's structure (controllers don't touch SQL, models don't
touch HTTP, validation goes through `FormRequest`) is what keeps async code honest — most of
them catch a mistake a Laravel habit would otherwise walk straight into.

## The rules

| Rule | Forbids | Why |
|---|---|---|
| A1 | `app/http/controllers/` importing `sqlalchemy` | Queries belong on the model, not the controller — keeps controllers testable without a database shape in mind. |
| A2 | A model importing `fastapi`, `starlette`, or `aso.http` | A model must work with no HTTP request in flight — in a job, a command, a seeder. |
| A3 | A controller reading raw input (`request.input()`, `request.json()`) | Forces validation through a `FormRequest`, so nothing unvalidated reaches a model. |
| A4 | An `inertia("some/page")` call with no matching page file | Catches a typo'd or renamed component before it 404s for a real user. |
| A5 | Importing a third-party Inertia adapter (`cross_inertia`, `inertia`) | One Inertia implementation (`aso.inertia`), not two competing ones in the same app. |
| A6 | Interpolating raw SQL with an f-string, `%`, or `+` | SQL injection — bound `:name` parameters only. |
| A7 | `print()` or `breakpoint()` in `app/` | Use `from aso.log import log`; a stray `print` is noise in production logs, and a stray `breakpoint()` hangs a server process. |
| A8 | Subclassing Starlette's `BaseHTTPMiddleware` | `aso.http.Middleware`'s adapter is what makes `next(request)` behave like Laravel middleware expects. |
| A9 | Creating a SQLAlchemy engine/session by hand | One connection pool, managed by `aso.database.DB`, not several competing ones. |
| A10 | A class in `app/http/requests/` that doesn't extend `FormRequest` and end in `Request` | Keeps validation classes discoverable and consistent to name. |
| A11 | A model with neither `__fillable__` nor `__guarded__` | Forces a deliberate mass-assignment decision per model. |
| A12 | A job constructor taking a model instance instead of an id | A model isn't JSON-serializable, and a stale instance is wrong by the time a worker runs it. |
| A13 | Reading `os.environ`/`os.getenv()` outside `config/` | One place config values come from, so `config("app.name")` always reflects `.env`, including in tests that override it. |

## `AGENTS.md`

Every app ships an `AGENTS.md` at its root: the generator commands to prefer, this same A1-A13
list in short form, and the project's naming conventions. Point a coding agent at it before it
touches the codebase — the architecture tests catch a violation either way, but the file saves
a round trip of the agent writing something, the tests failing, and it figuring out why.

```bash
aso agents:update
```

Regenerates the rules section after you've changed something the file describes (added a
custom middleware alias, a named rate limiter) — it rewrites that section in place, keeping
anything you've added above or below it.

## Opting out

A rule is sometimes genuinely wrong for one file — a generated client, a vendored script. Drop
it from the whole suite:

```python
arch_preset("aso").without("A7").check()
```

Or scope it to specific packages:

```python
arch_preset("aso").ignoring("app.console.commands").check()
```

For a single line, an inline comment suppresses just that rule on just that line (check the
rule's own error message for the exact comment it looks for — each one documents itself when
it fires).

## Writing your own rule

`arch(*packages)` is the same fluent builder the built-in rules are written with — reach for it
if your team has its own convention worth enforcing the same way:

```python
from aso.testing.arch import arch

def test_jobs_only_import_from_app() -> None:
    arch("app.jobs").must_not_import("app.http").check()
```

## Coming from Laravel

| Laravel | Aso |
|---|---|
| PHPStan/Larastan rules (community) | Built in, shipped with every app |
| Code review catching a raw query in a controller | A1, enforced in CI by the test suite |
| `CLAUDE.md`/`.cursorrules` (hand-maintained) | `AGENTS.md`, partly generated by `aso agents:update` |

## Gotchas

- These are tests, not a separate `aso lint` step — they run wherever `pytest`/`aso test` runs,
  including CI, and a violation fails the build the same way a broken assertion would.
- `.without(...)` and `.ignoring(...)` apply to the whole `arch_preset("aso").check()` call in
  that test — scope them narrowly (a second, separate `test_architecture.py` test) rather than
  disabling a rule for the entire app in the one test every rule shares.
